Choose the FMP, stock and subsection

Select BSAI or GOA → Document part or stock → Regional component → Subsection. Both FMPs share one working JSON but have separate document details. Switching views preserves edits. Front matter, appendices and tables holds document-wide material; Whole stock holds shared material.

New documents contain TODO prompts, not current scientific findings. Replace prompts with approved content and sources. Check the heading before pasting. Include/exclude controls change exports without deleting text; whole-stock controls affect every subsection for the selected stock.

Hover over a control, or focus it using Tab, for a short hint. Escape dismisses it. Hints remain visible while the control has focus or the pointer is over the hint. Use Shift + Tab to move back.

Edit, copy and paste

Paste multiline narrative with Cmd + V. Text is plain: Markdown, HTML, TeX, code and Quarto shortcodes render literally. The editor does not import PDF prose, rich formatting, images or citations.

  • Copy whole subsection copies narrative, table, caption and source fields to this session's internal clipboard.
  • Cut subsection copies internally, then clears the content.
  • Paste copied subsection (replace) replaces the target and clears its author-review flag. It can copy across stocks and FMPs; review the target carefully.
  • Undo cut / paste restores one preceding internal cut or paste at its original target. It is not general typing history. The internal clipboard and undo do not survive a page reload.

Expand Table, caption and units to paste tab-separated spreadsheet rows: one header, 2–30 unique nonempty columns, equal-width rows, at most 1000 data rows. Preserve zeros, NA and empty cells explicitly; embedded cell tabs/newlines are unsupported. Supply a caption and units. Values stay text; the app calculates no totals, projections or unit conversions. Tables wider than seven columns split into panels, repeating the first two identifier columns.

Save, reopen, import and recover

The app autosaves after an 800 ms pause. Choose Save now and wait for Saved locally before closing, refreshing or stopping. Download working copy exports the complete JSON for both FMPs; retain a copy before imports or recovery.

Reopen saved file reloads the disk version. Download your session's edits first if saving failed or another session changed the file. Working files → Open a builder working copy (.json) validates an import, saves the current document, then replaces both FMPs. New document also preserves the preceding file before creating fresh TODO scaffolds.

Saves use atomic replacement and keep the latest 20 prior disk versions in appdata/backups/. For recovery, first download the current session, then import a chosen backup JSON through Working files. A failed save when a session ends attempts an additional appdata/recovery-*.json copy. Neither autosave nor recovery substitutes for a retained backup.

Concurrent sessions refuse to overwrite a changed disk file. Unknown schema versions, malformed JSON and files over 20 MB are rejected. Schema 1 imports migrate to schema 2 by adding an excluded optional sculpin appendix; existing content is retained. Never delete the working file to resolve an error.

Review, check HTML and export

Fill the selected FMP's document details. For each included subsection, supply content and a source/run/approval reference, enter the report year for which you reviewed that source, then mark author review. This year must match Report year; it need not be the source's publication year. Content edits and internal paste clear the review flag.

In Review and render, Working draft labels missing, placeholder, stale and unreviewed content. For review blocks rendering until all included items pass the checklist. Invalid tables must be fixed even for a draft. Choose HTML, Word and/or PDF, then Save and render selected FMP. Both FMPs are saved; only the selected FMP is rendered.

Open HTML QA/QC to check order, headings, content, tables, units and warning labels. Then inspect Word and PDF separately for page breaks, clipping, table panels and links. PDF needs Quarto, XeLaTeX and Times New Roman. Word uses inst/template.docx; update its table-of-contents field in Word.

Each render creates a new bundle and preserves previous runs. A format may fail while others succeed. Read the format status and log; only successful files receive output links. Return to this editor to revise and render again.

Find working files and outputs

Paths below are relative to ~/_mymods/Council/planteam/. Working files displays the active storage path; an explicit PLANTEAM_BUILDER_DATA setting can change working-file storage.

appdata/working.json
Editable document for both FMPs, including excluded material and review flags.
appdata/backups/ and appdata/recovery-*.json
Prior saved versions and any session-end recovery files.
_output/builder/<document-id>-<FMP>-<unique-suffix>/
The exact bundle path appears after rendering. It contains working-document.json, document.qmd, _quarto.yml, manifest.yml, logs and successful rendered/document.html, document.docx or document.pdf.
appdata/builder-service.log
Launcher/service diagnostics. Format logs are render-html.log, render-docx.log and render-pdf.log inside the bundle.

These directories are Git-ignored. Keep restricted inputs and derived documents on approved local storage; review every file before sharing. The app performs no automatic data fetch or external upload.

Common errors

Missing, stale or unreviewed
Replace TODO/example content, complete metadata/source fields, match the source-review year and review each included subsection. Exclude material intentionally outside the document.
Unequal-width table or duplicate headings
Paste true tabs, one unique header per column and the same number of cells per row. Add a caption with units.
Working file changed in another session
Download your session's working copy before reopening the disk file. Reconcile the copies explicitly; the app does not merge them.
Save locked or SAVE FAILED
Download a copy, read the error and check available disk space/permissions. Remove a stale working.json.lock directory only after confirming no app process is writing.
RENDER FAILED or a failed format
Check the checklist and retained log. Confirm Quarto, required R packages and, for PDF, XeLaTeX/font dependencies. Your saved document remains available. Fix the cause and render a new bundle.
Output link no longer opens
Browser output links belong to the session that rendered them. After a reload, close or restart, use the original files in the recorded bundle, or render again.

Start and stop on this Mac

Double-click Start Builder.command in the repository, then open http://127.0.0.1:3847/. Start reuses this checkout's healthy service. Save before double-clicking Stop Builder.command. Stop leaves documents and backups in place.

cd ~/_mymods/Council/planteam
/usr/bin/python3 scripts/manage-builder.py start
/usr/bin/python3 scripts/manage-builder.py status
# Save first, then stop when finished:
/usr/bin/python3 scripts/manage-builder.py stop

The on-demand Mac service survives terminal/task completion, stops at logout and does not start at boot/login. An occupied port from an unmanaged process is reported and left untouched. Read appdata/builder-service.log if the page will not load. After application R code changes, save, stop and start; refresh to load changed help/JavaScript/CSS. A refresh clears the session clipboard, undo and output links, so finish those actions first.

Local versus hosted

The current app runs on this Mac. Start it with Start Builder.command, then open http://127.0.0.1:3847/. A push stores source code on GitHub; it does not host the running app. GitHub Pages can show static documents but cannot run this R/Shiny and Quarto backend.

Hosting on a server is a separate deployment project. It would need R, the app packages, Quarto and the PDF dependencies, plus persistent storage, access controls, restricted-data review and separate drafts for each user. The current app uses one working JSON per storage directory; it is not ready for shared multiuser hosting. No server deployment is part of this local setup.

Before scientific release

Checklist completion records author checks; it does not establish scientific correctness, adopted management advice or release approval. Historical examples provide structure only. Check all current facts, calculations supplied by authors, sources, dates, units and approvals.

Review target Word pagination and the table of contents in Word. Inspect PDF layout separately. The PDF is currently untagged and has not been certified for Section 508. Keyboard/focus hints improve access to the editor; full screen-reader and accessibility conformance audits remain outstanding. Rich formatting, embedded images, automatic citations, multiuser merging and page-for-page historical reproduction are outside this editor's current capabilities.

For setup and detailed validation commands, read BUILDER.md and VALIDATION.md in the repository. This Help page and the app run locally; publication is a separate decision.
